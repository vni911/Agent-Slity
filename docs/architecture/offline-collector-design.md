# 기존 Codex 기록 가져오기 설계 초안

상태: 일부 라이브러리 구현 및 합성 테스트, 격리된 Linux 합성 기록의 제한된 실제 서버 조회 확인 · 상태 확인일: 2026-11-09 · 최초 설계 Issue #63, turn 수집 Issue #92. CLI는 사용자가 별도로 준비한 JSONL과 일부 응답만 정규화한다. 개인 기록 자동 가져오기와 Windows·WSL 지원은 검증하지 않았다. 격리 환경의 관측은 사용자 환경 지원을 보증하지 않는다.

## 현재 구현과 검증 범위

- `CodexReadTransport`는 호출자가 제공한 스트림에서 초기화와 제한된 읽기 요청을 처리한다. [전송 테스트](../../tests/unit/codex-read-transport.test.ts)는 합성 스트림으로 응답 ID 연결, 오류·시간 초과·취소 및 크기 제한 등을 확인한다.
- `collectCodexThreadPagesV0166`는 이미 초기화된 클라이언트와 지정된 스레드 ID를 사용해 스레드 및 항목 페이지를 정규화한다. [수집 테스트](../../tests/unit/thread-page-collector.test.ts)는 반복 커서·페이지 한도·ID 불일치·부분 결과를 확인한다.
- `collectFromChildV0166`는 **호출자가 생성한** 자식 프로세스의 소유권을 받아 수집 후 종료를 시도한다. `exit_observed`는 직접 자식의 종료 관측만 뜻하며 하위 프로세스 전체의 종료를 보증하지 않는다. [합성 서버 통합 테스트](../../tests/integration/collector.integration.mjs)는 별도 합성 프로세스의 페이지 수집·오류·취소와 종료 처리를 확인한다.
- 실행 파일 탐색·버전 자동 판별·실제 서버 시작·사용자 기록 자동 탐색을 제공하지 않는다. 합성 테스트는 실제 Codex App Server의 읽기 전용성, 네트워크나 파일 부작용, Windows·WSL 지원을 증명하지 않는다. 전체 메모리 사용의 엄격한 상한도 확인되지 않았다.

## 목표와 범위

사용자가 명시적으로 지정한 스레드 ID와 수집 범위에서 기존 메타데이터와 저장 항목을 모델 호출 없이 조회한다. 최초 구현은 **사용자 지정 ID**를 우선하며 자동 스레드 탐색을 포함하지 않는다. 이후 목록 기능은 별도 Issue에서 사용자 선택과 필터를 명시한다. 실행 기록 전체, 실시간 이벤트, 모델 사용량과 품질 검증 결과의 완전한 복구는 보장하지 않는다.

## 공식 인터페이스와 버전

[공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)에 따르면 stdio의 줄 단위 JSON 프로토콜에서 연결마다 `initialize` 성공 후 `initialized`를 보내야 한다. `thread/read`는 재개·구독 없이 메타데이터를 읽고, `thread/items/list`는 저장 항목을 페이지별로 읽지만 저장소에 따라 미지원일 수 있다. 설치된 CLI 0.166.0에서 생성한 스키마에서는 두 요청 모두 `threadId`가 필수다. 현재 공식 문서와 설치 버전은 항목 유형이 다르므로 [스키마 조사](../research/codex-app-server-schema.md)를 기준으로 버전별 지원을 판별하고 미지원 버전은 추측해 처리하지 않는다.

향후 목록 조회에서 기본 `sourceKinds`는 `cli`·`vscode`로 제한되고 보관된 스레드와 모델 공급자 필터도 결과 범위에 영향을 준다. `useStateDbOnly`를 생략하거나 `false`로 두면 JSONL 스캔과 메타데이터 복구가 일어날 수 있다. `true` 설정만으로 프로세스 전체가 무쓰기·무네트워크라는 보장은 없다. 실제 지원과 부작용은 별도로 검증한다. [공식 문서](https://learn.chatgpt.com/docs/app-server)

## 제안하는 전송·수집 경계

1. 사용자가 지정한 대상과 실행 환경, 실행 파일 경로와 버전을 확인하고 해당 버전의 어댑터를 선택한다. 실행 파일의 버전만으로 신뢰성을 보증하지 않는다. 프로세스 인수는 셸 문자열로 결합하지 않는다. 사용자의 명시적 수집 동작 전에는 서버를 실행하거나 기록을 탐색하지 않는다.
2. 전송 계층은 요청 ID로 응답을 연결하고 알림·서버 요청을 구분한다. 필요한 초기화와 지정된 읽기 메서드만 허용한다. 실행·재개·모델 호출·수정·삭제 메서드는 허용하지 않고 예상 밖 서버 요청은 안전하게 거부하거나 종료한다.
3. 원본 응답은 제한된 메모리에서 정규화기로 전달한다. 커서는 다음 요청에만 보관하고 내보내지 않는다. 현재 정규화기의 `next_page`는 커서 유무만 남기므로 이것만으로 다음 페이지를 가져올 수 없다.
4. 원문 메시지·프롬프트·명령·경로·커서·서버 stderr를 기본 결과나 오류에 복사하지 않는다. 식별자에도 민감정보가 들어갈 수 있으므로 출력 공개 전 사용자 검토가 필요하다. 정규화된 관측과 사용자 지정 별칭은 진위를 인증하지 않으며 `unverified`로 남긴다.
5. 프로세스 종료·시간 초과·취소·미지원·형식 오류·크기 제한·반복 커서·부분 응답은 사유와 함께 미완료로 기록한다. 응답, 줄, 페이지, 대기 시간 및 총 메모리에 상한을 두고 초과 시 조용히 잘라내지 않는다. stderr와 실패 원문은 노출하지 않는다.

페이지의 마지막 커서는 해당 요청 조건에서의 종료만 뜻한다. 목록 필터·접근 불가 스레드·미지원 항목·활성 실행의 저장 지연을 고려하면 전체 기록의 완전성을 증명하지 않는다. 중복·역순·충돌은 근거와 함께 보존하며 ID 일치만으로 동일 이벤트를 삭제하거나 관계를 확정하지 않는다. 수집 파라미터와 확인 가능한 버전, 각 요청의 완료·미완료 범위를 기록한다. 지원하지 않는 항목은 개수와 위치를 남기되 원문은 보존하지 않는다.

커서를 저장하지 않으면 중단 후 같은 위치에서 이어받는 것은 지원하지 않는다. 재조회 시 순서나 내용이 바뀔 수 있으므로 기존 관측을 덮어쓰지 않는다. 안전한 영구 체크포인트와 충돌 처리, 저장 수명은 별도 설계가 필요하다. 기존 JSON 내보내기의 범위와 향후 수집 결과 형식도 별도로 정하고, 현재의 JSONL 출력이 모든 저장 이벤트를 담는다고 주장하지 않는다.

`findThreadEvidenceCandidates`는 정규화된 스레드 관측과 항목 페이지에서 같은 출처 별칭과 스레드 ID가 명시된 후보를 연결한다. 입력 배열의 스레드·페이지·항목 위치와 수신자 위치를 유지하며 중복도 보존한다. 결과는 `unverified`이고 실제 동일 실행이나 부모 관계를 증명하지 않는다. 별칭은 호출자가 지정하므로 서로 다른 실행에 같은 별칭을 재사용하면 관련 없는 관측도 후보로 묶일 수 있다. 누락·미지원 관측과 일치하지 않는 값은 결과에서 생략되며, 이 함수만으로 누락이나 전체 수집 범위를 판정할 수 없다.

## 추가 검증과 수용 기준

- **합성 프로토콜 서버:** 위에 연결한 단위·통합 테스트가 일부 전송과 수집 실패를 검증한다. 모든 이벤트 누락·순서 역전과 모든 출력 경로의 민감정보 제외가 검증되었다고 해석하지 않는다. 필요할 때 누락 사례를 추가한다.
- **격리된 실제 서버:** [Issue #91](https://github.com/vni911/Agent-Slity/issues/91)에 Linux Codex 0.166.0의 합성 조회·파일 생성·차단된 DNS 시도와 실패·종료 관측을 기록했다. 무쓰기·무네트워크를 보증하지 않는다. 개인 기록·인증 정보·모델 호출·실행·수정 요청은 사용하지 않았다. 다른 환경과 전체 부작용은 미확인이다.
- **실사용 환경:** Windows·WSL 등 운영체제별 접근·경로·부작용과 사용자 지정 범위를 실제로 검증하기 전에는 지원을 주장하지 않는다. 권한 제한을 풀어 오류를 우회하지 않는다.

## full turn 페이지 수집 경로

`collectCodexTurnPagesV0166`는 이미 초기화된 읽기 클라이언트에 사용자가 지정한 스레드의 메타데이터를 요청한 뒤 `listTurns`를 호출한다. `CodexReadTransport.listTurns`는 `thread/turns/list`에 `itemsView: full`, `sortDirection: asc`, `limit: 100`을 명시한다. 기존 item 수집 API는 변경하지 않으며 자동 fallback하지 않는다. `collectFromChildV0166`도 기존 item 경로를 유지한다. 새 경로의 서버 생성·자원 종료는 호출자가 담당한다.

turn 페이지는 item 페이지와 별도 형식이다. `normalizeCodexTurnsPageV0166`는 full이 아닌 view나 손상된 item 배열을 미지원 페이지로 남긴다. turn의 중복과 순서 및 turn 안 item 인덱스를 보존한다. 반환된 ID는 저장 JSONL ID와 동일하다고 가정하지 않는다. userMessage·agentMessage는 유형·ID·제공된 item 시각만 남기고 본문은 제외한다. 기존 협업·명령·파일 변경 정규화는 페이지 전체에 합산 예산을 공유해 재사용하며 알 수 없는 유형은 위치를 남긴다.

페이지별 turn과 합산 item은 각각 10,000개로 제한한다. 협업 수신자와 파일 변경 중첩 예산도 각각 페이지당 10,000개이며 초과한 관측은 기존 정규화기처럼 null이다. 기본 10페이지·최대 20페이지이며 취소·서버 오류·전송 오류·반복 커서 등은 이전 페이지를 보존해 partial로 반환한다. summary·누락 view를 full 결과로 해석하지 않는다. 원문·커서·경로·stderr는 결과에 포함하지 않고 unverified를 유지한다. 제한 내에서도 전체 메모리의 엄격한 상한을 증명하지 않는다.

`tests/fixtures/isolated-turn-probe.mjs`는 개인 홈을 마운트하지 않은 비관리자·네트워크 없음·읽기 전용 루트·tmpfs 컨테이너에서 수동 실행하는 합성 검증이다. 실제 0.166.0에서 101개 turn과 202개 메시지를 100/1 turn 페이지로 수집하고 원본 JSONL 보존과 원문 제외를 확인했다. 다른 item 유형과 실제 사용자 기록의 완전 복원은 검증하지 않았다.

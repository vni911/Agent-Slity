# 기존 Codex 기록 가져오기 설계 초안

상태: 설계만 작성 · 확인일: 2026-11-03 · Issue #63. 현재 CLI는 사용자가 별도로 준비한 JSONL과 일부 응답만 정규화한다. 실제 App Server 조회, 저장 기록 자동 가져오기, WSL 지원과 읽기 전용 부작용은 검증하지 않았다. 이 문서의 기능과 시험은 아직 구현하지 않았다.

## 목표와 범위

사용자가 명시적으로 지정한 스레드 ID와 수집 범위에서 기존 메타데이터와 저장 항목을 모델 호출 없이 조회한다. 최초 구현은 **사용자 지정 ID**를 우선하며 자동 스레드 탐색을 포함하지 않는다. 이후 목록 기능은 별도 Issue에서 사용자 선택과 필터를 명시한다. 실행 기록 전체, 실시간 이벤트, 모델 사용량과 품질 검증 결과의 완전한 복구는 보장하지 않는다.

## 공식 인터페이스와 버전

[공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)에 따르면 stdio의 줄 단위 JSON 프로토콜에서 연결마다 `initialize` 성공 후 `initialized`를 보내야 한다. `thread/read`는 재개·구독 없이 메타데이터를 읽고, `thread/items/list`는 저장 항목을 페이지별로 읽지만 저장소에 따라 미지원일 수 있다. 설치된 CLI 0.166.0에서 생성한 스키마에서는 두 요청 모두 `threadId`가 필수다. 현재 공식 문서와 설치 버전은 항목 유형이 다르므로 [스키마 조사](../research/codex-app-server-schema.md)를 기준으로 버전별 지원을 판별하고 미지원 버전은 추측해 처리하지 않는다.

향후 목록 조회에서 기본 `sourceKinds`는 `cli`·`vscode`로 제한되고 보관된 스레드와 모델 공급자 필터도 결과 범위에 영향을 준다. `useStateDbOnly`를 생략하거나 `false`로 두면 JSONL 스캔과 메타데이터 복구가 일어날 수 있다. `true` 설정만으로 프로세스 전체가 무쓰기·무네트워크라는 보장은 없다. 실제 지원과 부작용은 별도로 검증한다. [공식 문서](https://learn.chatgpt.com/docs/app-server)

## 제안하는 전송·수집 경계

1. 사용자가 지정한 대상과 실행 환경, 실행 파일 경로와 버전을 확인하고 해당 버전의 어댑터를 선택한다. 실행 파일의 버전만으로 신뢰성을 보증하지 않는다. 프로세스 인수는 셸 문자열로 결합하지 않는다. 사용자의 명시적 수집 동작 전에는 서버를 실행하거나 기록을 탐색하지 않는다.
2. 전송 계층은 요청 ID로 응답을 연결하고 알림·서버 요청을 구분한다. 필요한 초기화와 지정된 읽기 메서드만 허용한다. 실행·재개·모델 호출·수정·삭제 메서드는 허용하지 않고 예상 밖 서버 요청은 안전하게 거부하거나 종료한다.
3. 원본 응답은 제한된 메모리에서 정규화기로 전달한다. 커서는 다음 요청에만 보관하고 내보내지 않는다. 현재 정규화기의 `next_page`는 커서 유무만 남기므로 이것만으로 다음 페이지를 가져올 수 없다.
4. 원문 메시지·프롬프트·명령·경로·커서·서버 stderr를 기본 결과나 오류에 복사하지 않는다. 식별자에도 민감정보가 들어갈 수 있으므로 출력 공개 전 사용자 검토가 필요하다. 정규화된 관측과 사용자 지정 별칭은 진위를 인증하지 않으며 `unverified`로 남긴다.
5. 프로세스 종료·시간 초과·취소·미지원·형식 오류·크기 제한·반복 커서·부분 응답은 사유와 함께 미완료로 기록한다. 응답, 줄, 페이지, 대기 시간 및 총 메모리에 상한을 두고 초과 시 조용히 잘라내지 않는다. stderr와 실패 원문은 노출하지 않는다.

페이지의 마지막 커서는 해당 요청 조건에서의 종료만 뜻한다. 목록 필터·접근 불가 스레드·미지원 항목·활성 실행의 저장 지연을 고려하면 전체 기록의 완전성을 증명하지 않는다. 중복·역순·충돌은 근거와 함께 보존하며 ID 일치만으로 동일 이벤트를 삭제하거나 관계를 확정하지 않는다. 수집 파라미터와 확인 가능한 버전, 각 요청의 완료·미완료 범위를 기록한다. 지원하지 않는 항목은 개수와 위치를 남기되 원문은 보존하지 않는다.

커서를 저장하지 않으면 중단 후 같은 위치에서 이어받는 것은 지원하지 않는다. 재조회 시 순서나 내용이 바뀔 수 있으므로 기존 관측을 덮어쓰지 않는다. 안전한 영구 체크포인트와 충돌 처리, 저장 수명은 별도 설계가 필요하다. 기존 JSON 내보내기의 범위와 향후 수집 결과 형식도 별도로 정하고, 현재의 JSONL 출력이 모든 저장 이벤트를 담는다고 주장하지 않는다.

## 구현 전 검증과 수용 기준

- **합성 프로토콜 서버:** 초기화 순서, 분할된 줄, 교차 응답 ID, 알림과 역방향 요청, 미지원 메서드, 잘못된 JSON, 크기·시간 제한, 취소와 조기 종료를 테스트한다. 페이지 중복·순서 역전·누락·반복 커서와 각 실패의 미완료 상태를 확인한다. 비밀을 흉내 낸 값이 표준 출력·오류·내보내기에 나타나지 않는지도 검사한다.
- **격리된 실제 서버:** 개인 기록과 인증 정보가 없는 합성 전용 환경을 준비하고 접근 범위를 검증한 뒤, 같은 버전의 프로세스 전후 파일 변경과 네트워크 활동을 관찰한다. 환경변수나 임시 홈만으로 격리가 완전하다고 간주하지 않는다. 모델 호출이나 실행·수정 메서드를 사용하지 않는다. 이 검증은 별도 구현 단계의 작업이며 아직 수행하지 않았다.
- **실사용 환경:** Windows·WSL 등 운영체제별 접근·경로·부작용과 사용자 지정 범위를 실제로 검증하기 전에는 지원을 주장하지 않는다. 권한 제한을 풀어 오류를 우회하지 않는다.

다음 구현 Issue는 합성 서버와 제한된 프로토콜 전송 계층을 먼저 다루고, 실제 서버 연결 및 부작용 검증은 그 결과를 보고 별도로 진행한다.

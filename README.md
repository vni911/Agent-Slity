# Agent Slity

[English](README.en.md) · [한국어 README 사본](README.ko.md)

**작업에 꼭 필요한 팀을 구성하고 실행하세요.**

Agent Slity는 멀티에이전트 협업의 실제 효율을 측정하기 위한 오픈소스 개발자 도구를 개발하는 프로젝트입니다. 검증된 작업 품질을 유지하면서 중복 탐색, 불필요한 위임, 대기와 재시도를 줄이는 것이 목표입니다.

## 현재 상태

**1단계 수집 기반을 개발 중입니다.** 사용자가 지정한 JSONL 파일을 읽고 일부 Codex 실행 이벤트를 공통 형식으로 정리하는 라이브러리와 개발용 CLI를 제공합니다. 원본을 수정하거나 모델을 호출하지 않습니다. 설치 가능한 앱, 스레드 연결, 보고서 생성기와 데스크톱 UI는 아직 없습니다. 반환된 값에는 민감정보가 포함될 수 있으므로 공개 전에 검토해야 합니다.

초기 대상 환경은 Windows 11, WSL2 Ubuntu, Codex CLI입니다. 실제 지원 여부는 아직 검증하지 않았습니다. WSL 없는 Windows, Linux, macOS는 향후 대상입니다.

프로젝트 이름은 Agent Slity이며 저장소 이름은 `Agent-Slity`입니다. Google이나 OpenAI의 공식 제품이 아닌 독립 프로젝트입니다.

### 현재 JSONL 읽기 범위

라이브러리의 `readJsonlFile(path, options)`는 JSON 값을 순서와 1부터 시작하는 줄 번호로 반환합니다. 빈 줄은 건너뛰고 중복 값은 보존합니다. 잘못된 JSON·UTF-8이나 크기 제한 초과는 원문 없는 진단으로 반환하고 다음 줄을 계속 읽습니다. 줄 앞 BOM은 `invalid_json`으로 진단합니다. 기본 제한은 원본 기준 줄당 8 MiB이며 줄바꿈 LF는 제외하고 CR은 포함합니다. `maxLineBytes`로 제한을 변경할 수 있습니다. 읽기 실패는 파일 경로를 포함하지 않는 `JsonlReadError`를 발생시킵니다.

리더가 반환하는 값은 원본 JSON인 `unknown`이며 민감한 내용을 포함할 수 있습니다. 기록의 출처·완전성·실제 Codex 저장 형식 호환성은 별도 확인이 필요합니다. CLI 실행이나 기존 세션 자동 탐색은 하지 않습니다.

### 현재 이벤트 정규화 범위

`normalizeCodexExecLine`은 리더의 한 줄을 받아 공식 `codex exec --json` 문서에 예시된 제한된 이벤트 유형만 변환합니다. 명시된 스레드 ID와 완료 이벤트의 사용량만 복사하며, 확인되지 않은 값은 `null`로 남기고 실제 0은 보존합니다. 메시지·명령 원문은 결과에 포함하지 않습니다. 미지원 입력과 손상 진단은 줄 번호와 함께 별도로 반환합니다.

`normalizeCodexExecLine(line, "source_1")`처럼 선택적 출처 별칭을 지정하면 이벤트·진단·미지원 결과에 보존합니다. 별칭은 영문자·숫자·밑줄·하이픈 1~64자이며, 생략하면 `null`입니다. 파일별로 서로 다른 별칭을 관리할 책임은 호출자에게 있습니다. 별칭에 경로나 민감정보를 넣지 마세요.

파일 내용과 별칭의 진위는 확인하지 않으므로 `verification_status`는 `unverified`입니다. 형식 버전·수집 시각은 아직 알 수 없고, 스레드 연결·사용량 합산·중복 제거는 수행하지 않습니다. 식별자에도 민감정보가 포함될 수 있으므로 결과를 자동으로 공개하지 마세요.

`exportNormalizationJson(results)`는 정규화 결과 배열을 형식 버전이 포함된 JSON 문자열로 반환합니다. 이벤트·진단·미지원 결과의 순서와 중복을 보존하며 파일을 쓰지 않습니다. 결과 전체를 메모리에 담으므로 큰 기록에는 주의하세요. 출력에 스레드 ID와 출처 별칭이 포함될 수 있어 공유 전에 민감정보를 확인해야 합니다.

## 측정하려는 내용

- 여러 에이전트의 동일 파일·문서·명령 반복 탐색
- 작업 위임, 메시지 전달, 유휴 시간, 실패와 재시도
- 코드 변경에 대한 실제 검증 근거의 유무
- 요청한 모델 설정과 실행 중 관측한 증거의 차이
- 비교 가능한 팀 구성별 품질, 실행 시간, 관측된 사용량

모두 계획 중인 기능이며 구현이나 개선 효과를 입증한 상태가 아닙니다. 에이전트 수가 적다는 사실만으로 성공을 판단하지 않습니다. [0.2 선행 조사](docs/research/competitor-analysis.md)에서 주요 중복을 확인했으며, 차별화 가설과 성능 개선은 검증이 필요합니다.

## 데이터와 개인정보

첫 수집기는 모델 호출 없이 기존 로컬 Codex 실행 기록을 가져오는 방식으로 계획하고 있습니다. 출처와 불확실성을 보존하며, 사용량이 없으면 0이 아닌 `unknown`으로 남깁니다. 분석에서는 확인된 관측, 비효율 의심, 판단 정보 부족을 구분합니다.

자동으로 로그를 수집하지 않습니다. 공개 예제에는 합성 기록을 사용합니다. 인증 파일, 비밀 정보, 개인 대화와 원본 실행 로그를 Issue나 PR에 첨부하지 마세요. [보안 지침](SECURITY.md)을 확인하세요.

## 시작하기

개발용 CLI를 사용하려면 Node.js 24와 Git을 설치한 뒤 저장소 루트에서 다음을 실행하세요.

```sh
npm ci
npm run check
```

`npm run check`는 타입 검사, 린트, 단위 테스트, 빌드와 CLI 프로세스 통합 테스트를 순서대로 실행합니다. 통합 테스트만 실행하려면 먼저 `npm run build`를 실행한 뒤 `npm run test:integration`을 사용하세요. Windows PowerShell에서는 `npm.cmd`를 사용할 수 있습니다. [기여 절차](CONTRIBUTING.md)와 [에이전트 작업 지침](AGENTS.md)도 확인하세요.

합성 예제의 정규화 결과를 모델 호출 없이 확인하려면 다음을 실행하세요.

```sh
node dist/cli/main.js tests/fixtures/demo.jsonl demo
```

직접 지정한 JSONL에도 같은 명령을 사용할 수 있습니다. 두 번째 인수는 선택적인 출처 별칭입니다. 결과는 표준 출력에만 표시하며 전체 결과를 메모리에 담습니다. 실제 Codex 저장 기록과의 호환성은 확인 필요입니다. 출력에는 민감한 식별자가 포함될 수 있으므로 공유 전에 확인하세요. 셸 리디렉션으로 결과를 저장할 때는 원본과 다른 파일을 지정하세요. 같은 파일을 지정하면 셸이 원본을 덮어쓸 수 있습니다.

# Agent Slity

[기본 README](README.md) · [English](README.en.md)

**작업에 꼭 필요한 팀을 구성하고 실행하세요.**

Agent Slity는 멀티에이전트 협업의 실제 효율을 측정하기 위한 오픈소스 개발자 도구를 개발하는 프로젝트입니다. 검증된 작업 품질을 유지하면서 중복 탐색, 불필요한 위임, 대기와 재시도를 줄이는 것이 목표입니다.

## 현재 상태

**1단계 수집 기반을 개발 중입니다.** 사용자가 지정한 JSONL 파일을 읽고 일부 Codex 실행 이벤트를 공통 형식으로 정리하는 라이브러리와 개발용 CLI를 제공합니다. 원본을 수정하거나 모델을 호출하지 않습니다. 설치 가능한 앱, 스레드 연결, 보고서 생성기와 데스크톱 UI는 아직 없습니다. 반환된 값에는 민감정보가 포함될 수 있으므로 공개 전에 검토해야 합니다.

초기 대상 환경은 Windows 11, WSL2 Ubuntu, Codex CLI입니다. 실제 지원 여부는 아직 검증하지 않았습니다. WSL 없는 Windows, Linux, macOS는 향후 대상입니다.

프로젝트 이름은 Agent Slity이며 저장소 이름은 `Agent-Slity`입니다. Google이나 OpenAI의 공식 제품이 아닌 독립 프로젝트입니다.

### 현재 JSONL 읽기 범위

라이브러리의 `readJsonlFile(path, options)`는 JSON 값을 순서와 1부터 시작하는 줄 번호로 반환합니다. 빈 줄은 건너뛰고 중복 값은 보존합니다. 잘못된 JSON·UTF-8이나 크기 제한 초과는 원문 없는 진단으로 반환하고 다음 줄을 계속 읽습니다. 줄 앞 BOM은 `invalid_json`으로 진단합니다. 기본 제한은 원본 기준 줄당 8 MiB이며 줄바꿈 LF는 제외하고 CR은 포함합니다. `maxLineBytes`로 제한을 변경할 수 있습니다. 읽기 실패는 파일 경로를 포함하지 않는 `JsonlReadError`를 발생시킵니다.

리더가 반환하는 값은 원본 JSON인 `unknown`이며 민감한 내용을 포함할 수 있습니다. 기록의 출처·완전성·실제 Codex 저장 형식 호환성은 별도 확인이 필요합니다. CLI 실행이나 기존 세션 자동 탐색은 하지 않습니다.

### 현재 이벤트 정규화 범위

저장 협업 항목의 turn·항목·송신·수신 ID는 각각 최대 256 UTF-16 코드 단위입니다. 초과 값은 자르지 않고 `null`로 두며, 수신 배열의 위치와 중복은 보존합니다. 출력에서는 초과와 누락을 구분하지 않습니다. 이전 버전에서 출력되던 긴 ID가 `null`로 바뀌므로 기존 소비자와의 호환성은 확인 필요입니다.

0.166.0 스키마의 `subAgentActivity` 항목은 `subagent_activity`로 정규화해 명시된 스레드·항목·turn ID, 활동 종류, 보고된 모델·추론 설정을 보존합니다. 문자열은 각각 최대 256 UTF-16 코드 단위이며 누락·잘못된 값·초과는 `null`입니다. 에이전트 경로와 메시지 원문은 복사하지 않지만 ID와 설정값에 민감정보가 있을 수 있습니다. 입력은 `unverified`이며 설정값은 실제 사용량이나 성능의 증거가 아닙니다. 이전에 미지원이던 항목이 새 유형으로 표시되므로 엄격한 소비자와의 호환성은 확인 필요입니다.

`collectFromChildV0166`은 호출자가 이미 생성한 자식 프로세스와 파이프의 소유권을 넘겨받아 초기화·단일 스레드 수집 후 스트림을 닫고 자식 종료를 시도합니다. `cleanup_status: exit_observed`는 직접 자식의 종료가 관측됐다는 뜻이며 성공적인 종료, 파이프의 완전한 정리나 하위 프로세스 전체 종료를 보증하지 않습니다. 시간 내 종료를 확인하지 못하면 `unknown`입니다. stderr 원문은 버리고 실행 파일 선택과 버전 검증은 호출자가 책임집니다. 합성 서버만 검증했으며 실제 Codex 실행·격리, 파일·네트워크 부작용 및 사용자 기록 연동은 확인 필요입니다.

`collectCodexThreadPagesV0166`은 이미 초기화된 읽기 클라이언트에서 사용자가 지정한 스레드와 항목 페이지를 정규화합니다. 기본 10페이지, 최대 20페이지이며 반복·누락 커서, 오류·취소와 한도는 부분 결과와 사유로 남깁니다. 취소 후에도 클라이언트가 자체 요청을 중단하는지는 구현에 달려 있으며 자원 종료는 호출자 책임입니다. `last_page`는 해당 요청의 마지막 페이지만 뜻하며 기록 전체의 완전성을 증명하지 않습니다. 커서·메시지 원문은 결과에 넣지 않지만 ID는 민감할 수 있습니다. 버전 확인은 호출자 책임이며 0.166.0 기준을 선택한 합성 스트림만 검증했습니다. 실제 프로세스 실행·기록 자동 탐색 및 서버 연동은 제공하지 않습니다.

`CodexReadTransport`는 호출자가 제공하는 스트림에서 초기화와 제한된 읽기 요청을 교환하는 실험적 라이브러리입니다. 종료 시 전달받은 스트림을 파괴하며 `close` 이벤트를 내보내는 스트림이 필요합니다. 합성 스트림으로만 검증했으며 프로세스 실행·기록 자동 수집·CLI 연결은 아직 없습니다. 성공 응답은 정규화 전 원본 객체이므로 민감정보가 포함될 수 있습니다. 실제 App Server·WSL 연동과 부작용은 확인 필요입니다. [수집 설계](docs/architecture/offline-collector-design.md)를 참고하세요.

`thread/read` 정규화 결과의 `parent_thread_id_status`는 유효한 ID를 `present`, 명시적 `null`을 `explicit_null`, 누락·잘못된 값·접근 불가를 `unknown`으로 구분합니다. 명시적 `null`도 실제 루트 스레드라는 증거는 아닙니다. 이전 결과에는 이 필드가 없을 수 있으며 관측 불가로 취급해야 합니다. 부모 후보의 `unassociated`에도 이 상태를 보존하고 ID와 상태가 모순되면 `unknown`으로 둡니다. 후보 그룹은 상태를 검증하지 않고 ID 일치만 표시합니다. 이 필드는 기존 출력에 추가되며 추가 필드를 거부하는 소비자와의 호환성은 확인 필요입니다.

`findParentThreadCandidates(results)`는 정규화된 `thread/read` 결과에서 같은 출처 별칭의 명시적 부모 ID와 스레드 ID가 일치하는 입력 인덱스를 검토 후보로 묶습니다. 순서·중복·상충 기록과 출처 또는 부모 ID 누락, 후보 부재를 보존합니다. 자기 자신의 ID도 일치하면 후보에 포함하며 세션·포크 ID로 관계를 추정하지 않습니다. ID 일치는 실제 부모 관계나 실행을 증명하지 않으며 결과는 `unverified`입니다. ID는 민감할 수 있고 전체 결과를 메모리에 보관합니다.

개발용 CLI에서 한 줄에 `thread/read`의 `result` 객체 하나가 담긴 JSONL의 부모 후보를 확인할 수 있습니다. 다음은 합성 예제입니다. 후보 인덱스는 출력의 `records` 배열 기준이며, 각 레코드의 `line`과 `input_index`로 원래 위치를 확인합니다. `input_index`는 빈 줄을 제외하고 손상 진단을 포함한 0 기반 순서입니다. 결과 전체를 메모리에 보관하며 ID에 민감정보가 있을 수 있습니다.

```sh
node dist/cli/main.js --parents-jsonl tests/fixtures/parent-candidates-demo.jsonl sample
```

`normalizeCodexItemsPageV0166`은 `thread/items/list`의 `result` 객체 한 페이지에서 0.166.0 스키마의 `collabAgentToolCall` 항목에 명시된 turn·항목·송신·수신 ID와 도구·상태를 추출합니다. 중복과 순서, 미지원 항목을 보존하고 빠진 값은 `null`로 둡니다. `next_page`는 커서의 유무만 표시하며 페이지 전체 또는 실행 기록의 완전성을 증명하지 않습니다. 커서·프롬프트·메시지 원문은 출력하지 않지만 ID는 민감할 수 있습니다. 한 페이지 항목과 전체 수신 ID는 각각 최대 10,000개입니다. 초과 항목 페이지는 미지원이며, 전체 수신 ID 제한을 초과하는 항목의 수신 ID는 `null`입니다. 수신 ID의 누락과 제한 초과는 구분하지 않습니다. 스키마 전체와 진위는 검증하지 않고 결과는 `unverified`입니다. 서버 조회와 모델 호출은 하지 않습니다.

개발용 CLI에서 한 줄에 페이지 `result` 객체 하나가 담긴 JSONL을 처리할 수 있습니다. 다음 합성 예제는 중복 페이지와 손상 진단을 보여 줍니다. 줄당 기본 크기 제한은 8 MiB이며, 결과 전체를 메모리에 보관하므로 큰 입력에 주의하세요. ID에는 민감정보가 있을 수 있어 공유 전에 확인해야 합니다.

```sh
node dist/cli/main.js --items-page-jsonl tests/fixtures/items-page-demo.jsonl sample
```

`normalizeCodexThreadReadV0166`은 JSON-RPC 응답 전체가 아닌 `thread/read`의 `result` 객체를 받아 명시적 스레드·부모·세션·분기 출처 ID를 각각 보존합니다. 스레드 ID가 없으면 미지원 결과이며, 그 밖의 누락된 ID는 스키마의 필수 여부와 관계없이 `null`로 둡니다. 기준인 `0.166.0`은 호출자가 선택한 스키마 참조이며 입력의 전체 스키마·실제 버전·진위를 검증하지 않습니다. 결과는 `unverified`이고 ID에는 민감정보가 있을 수 있습니다. 서버나 Codex CLI 실행, 기록 수집은 하지 않습니다. [스키마 조사](docs/research/codex-app-server-schema.md)를 참고하세요.

개발용 CLI는 한 줄에 `result` 객체 하나가 담긴 JSONL을 읽습니다. 다음 합성 예제는 순서·줄 번호·중복과 손상 진단을 보존해 표준 출력으로 표시합니다. 전체 결과가 메모리에 저장되며 식별자에 민감정보가 있을 수 있습니다. 서버 실행이나 세션 자동 탐색은 하지 않습니다.

```sh
node dist/cli/main.js --thread-read-jsonl tests/fixtures/thread-read-demo.jsonl sample
```

`normalizeCodexExecLine`은 리더의 한 줄을 받아 공식 `codex exec --json` 문서에 예시된 제한된 이벤트 유형만 변환합니다. 명시된 스레드 ID, 지원되는 항목 유형과 완료 이벤트의 사용량을 보존하며, 확인되지 않은 값은 `null`로 남기고 실제 0은 보존합니다. 메시지·명령 원문은 결과에 포함하지 않습니다. 미지원 입력과 손상 진단은 줄 번호와 함께 별도로 반환합니다.

항목 시작·완료 이벤트에서는 공식 예시의 `command_execution`과 `agent_message` 유형만 `payload.item_type`으로 보존합니다. 다른 유형이나 정보 부족은 `null`이며, 유형만으로 실행 성공이나 메시지 전달을 판단하지 않습니다. 버전 1 JSON에 추가된 필드로, 이전 결과에 필드가 없으면 내보낼 때 `null`로 처리합니다.

항목 이벤트에 직접 제공된 `item.id`는 `payload.item_id`로 보존합니다. 이는 이벤트·스레드·에이전트 ID와 다르며 같은 실행이나 부모 관계를 증명하지 않습니다. 항목 ID에도 민감정보가 들어 있을 수 있으므로 공유 전에 확인하세요. 이전 결과에 ID 필드가 없으면 `null`로 내보냅니다. 버전 1 JSON의 추가 필드를 거부하는 기존 소비자와의 호환성은 확인 필요입니다.

`groupItemObservations(results)`는 같은 출처 별칭과 항목 ID를 가진 항목 이벤트를 검토 후보로 묶어 입력 인덱스·줄 번호·이벤트 유형·항목 유형과 명시적 스레드 ID를 보존합니다. 별칭이나 ID가 없는 항목 이벤트는 누락 사유와 함께 별도로 표시합니다. 같은 값이 실제 같은 항목이나 실행을 증명하지 않으며, 중복·순서 역전·유형 차이를 수정하지 않습니다. 결과는 미검증이며 식별자에 민감정보가 있을 수 있습니다. 전체 결과를 메모리에 복사하므로 큰 입력에 주의하세요.

`groupThreadObservations(results)`는 직접 제공된 스레드 ID와 출처 별칭이 같은 이벤트를 검토 후보로 묶고 위치와 항목 근거를 보존합니다. ID가 없는 이벤트는 앞선 스레드에 연결하지 않고 누락 사유와 함께 남깁니다. 손상 진단과 미지원 기록도 별도로 표시합니다. 같은 값이 실제 동일 스레드나 부모·자식 관계를 증명하지 않습니다. 식별자는 민감할 수 있고 전체 결과가 메모리에 복사됩니다.

`normalizeCodexExecLine(line, "source_1")`처럼 선택적 출처 별칭을 지정하면 이벤트·진단·미지원 결과에 보존합니다. 별칭은 영문자·숫자·밑줄·하이픈 1~64자이며, 생략하면 `null`입니다. 파일별로 서로 다른 별칭을 관리할 책임은 호출자에게 있습니다. 별칭에 경로나 민감정보를 넣지 마세요.

파일 내용과 별칭의 진위는 확인하지 않으므로 `verification_status`는 `unverified`입니다. 형식 버전·수집 시각은 아직 알 수 없고, 스레드 연결·사용량 합산·중복 제거는 수행하지 않습니다. 식별자에도 민감정보가 포함될 수 있으므로 결과를 자동으로 공개하지 마세요.

`exportNormalizationJson(results)`는 정규화 결과 배열을 형식 버전이 포함된 JSON 문자열로 반환합니다. 이벤트·진단·미지원 결과의 순서와 중복을 보존하며 파일을 쓰지 않습니다. 결과 전체를 메모리에 담으므로 큰 기록에는 주의하세요. 출력에 스레드 ID와 출처 별칭이 포함될 수 있어 공유 전에 민감정보를 확인해야 합니다.

`findSourceOverlaps(results)`는 같은 출처 별칭과 줄 번호가 반복된 후보를 0부터 시작하는 입력 인덱스로 표시합니다. `matching_normalized`는 정규화 결과만 같다는 뜻이며, 원본이나 실제 이벤트의 동일성을 보장하지 않습니다. 결과가 다른 그룹은 `conflict`로 표시하고 어떤 입력도 삭제하지 않습니다. 별칭이 없으면 비교하지 않으며, 출처별 별칭을 관리할 책임은 호출자에게 있습니다. 전체 결과를 메모리에 복사하므로 큰 입력에 주의하세요.

## 측정하려는 내용

- 여러 에이전트의 동일 파일·문서·명령 반복 탐색
- 작업 위임, 메시지 전달, 유휴 시간, 실패와 재시도
- 코드 변경에 대한 실제 검증 근거의 유무
- 요청한 모델 설정과 실행 중 관측한 증거의 차이
- 비교 가능한 팀 구성별 품질, 실행 시간, 관측된 사용량

모두 계획 중인 기능이며 구현이나 개선 효과를 입증한 상태가 아닙니다. 에이전트 수가 적다는 사실만으로 성공을 판단하지 않습니다. [0.2 선행 조사](docs/research/competitor-analysis.md)에서 주요 중복을 확인했으며, 차별화 가설과 성능 개선은 검증이 필요합니다.

## 데이터와 개인정보

첫 수집기는 모델 호출 없이 기존 로컬 Codex 실행 기록을 가져오는 방식으로 계획하고 있습니다. 출처와 불확실성을 보존하며, 사용량이 없으면 0이 아닌 `unknown`으로 남깁니다. 분석에서는 확인된 관측, 비효율 의심, 판단 정보 부족을 구분합니다.

자동으로 로그를 수집하지 않습니다. 공개 예제에는 합성 기록을 사용합니다. 인증 파일, 비밀 정보, 개인 대화와 원본 실행 로그를 Issue나 PR에 첨부하지 마세요. [보안 지침](SECURITY.md)을 확인하세요.

## 시작하기

개발용 CLI를 사용하려면 Node.js 24와 Git을 설치한 뒤 저장소 루트에서 다음을 실행하세요.

```sh
npm ci
npm run check
```

`npm run check`는 타입 검사, 린트, 단위 테스트, 빌드와 CLI 프로세스 통합 테스트를 순서대로 실행합니다. 통합 테스트만 실행하려면 먼저 `npm run build`를 실행한 뒤 `npm run test:integration`을 사용하세요. Windows PowerShell에서는 `npm.cmd`를 사용할 수 있습니다. [기여 절차](CONTRIBUTING.md)와 [에이전트 작업 지침](AGENTS.md)도 확인하세요.

합성 예제의 정규화 결과를 모델 호출 없이 확인하려면 다음을 실행하세요.

```sh
node dist/cli/main.js tests/fixtures/demo.jsonl demo
```

실행법과 주의사항은 `node dist/cli/main.js --help`로도 확인할 수 있습니다.

직접 관측된 스레드 ID별 후보를 확인하려면 파일 경로를 바꾸고 필수 출처 별칭을 지정합니다.

```sh
node dist/cli/main.js --threads my-run.jsonl sample
```

명시적 ID가 없는 이벤트, 진단과 미지원 기록도 위치·사유와 함께 남습니다. 같은 ID와 별칭은 실제 동일 스레드나 부모·자식 관계를 증명하지 않습니다. 인덱스는 빈 줄을 제외한 정규화 결과 기준입니다. 스레드·항목 ID가 출력에 포함될 수 있고 전체 결과를 메모리에 담으므로 공유와 대용량 입력에 주의하세요.

지정한 JSONL의 항목 관측 후보를 보려면 다음 명령에서 파일 경로를 바꿔 실행합니다. 출처 별칭은 필수입니다.

```sh
node dist/cli/main.js --items my-run.jsonl sample
```

결과는 별칭과 항목 ID가 일치하는 후보이며 실제 같은 실행이나 스레드 관계를 증명하지 않습니다. 중복과 순서 차이를 보존하고, 항목 ID가 없으면 인덱스·줄 번호와 누락 사유를 표시합니다. 손상 진단과 미지원 기록도 위치와 코드 또는 사유로 표시하며, 다른 이벤트는 인덱스로 표시합니다. 인덱스는 빈 줄을 제외한 정규화 결과 기준입니다. 항목·스레드 ID에 민감정보가 있을 수 있으며 전체 결과를 메모리에 담으므로 공유와 대용량 입력에 주의하세요.

정규화 JSON을 새 파일로 저장하려면 명시적으로 `--output`을 사용합니다.

```sh
node dist/cli/main.js --output tests/fixtures/demo.jsonl demo-result.json demo
```

입력을 끝까지 처리한 뒤 새 파일만 생성하며 기존 파일이나 입력 파일은 덮어쓰지 않습니다. 저장 실패 시 일부 작성된 새 파일이 남을 수 있으니 확인하세요. POSIX에서는 생성 권한 0600을 요청합니다. Windows에서는 권한 처리가 다를 수 있으므로 파일 접근 권한을 직접 확인하세요. 결과에 민감한 식별자가 포함될 수 있으므로 공유 전에 검토해야 합니다.

Windows에서는 기존 파일의 대체 데이터 스트림과 장치 경로를 출력 대상으로 허용하지 않습니다.

입력에서 읽힌 이벤트 유형, 미지원 사유와 진단 코드의 건수는 다음 명령으로 확인합니다.

```sh
node dist/cli/main.js --summary tests/fixtures/demo.jsonl
```

이 숫자는 빈 줄을 제외한 정규화 결과 수이며 중복을 포함합니다. 실제 고유 이벤트 수나 기록 누락률을 뜻하지 않고, 파일의 진위도 확인하지 않습니다. 파일을 순서대로 읽어 집계하며 원문과 경로는 출력하지 않습니다.

동일 출처라고 사용자가 지정한 두 기록의 위치 중복 후보를 확인할 수 있습니다. 다음 명령은 같은 합성 예제를 두 번 읽습니다.

```sh
node dist/cli/main.js --overlaps demo tests/fixtures/demo.jsonl tests/fixtures/demo.jsonl
```

출력의 `inputs`는 입력 순서별 시작 인덱스와 결과 수를 나타냅니다. 인덱스는 빈 줄을 제외한 정규화 결과의 0 기반 위치입니다. `matching_normalized`는 원본 일치를 증명하지 않으며, 같은 별칭을 다른 출처에 사용하면 후보가 잘못 묶일 수 있습니다. 경로와 원문은 출력하지 않고 입력도 삭제하지 않습니다.

일반 단일 파일 명령에는 직접 지정한 JSONL을 사용할 수 있으며 두 번째 인수는 선택적인 출처 별칭입니다. 일반 명령은 표준 출력만 사용하며 전체 결과를 메모리에 담습니다. 실제 Codex 저장 기록과의 호환성은 확인 필요입니다. 출력에는 민감한 식별자가 포함될 수 있으므로 공유 전에 확인하세요. 셸 리디렉션으로 결과를 저장할 때는 원본과 다른 파일을 지정하세요. 같은 파일을 지정하면 셸이 원본을 덮어쓸 수 있습니다.

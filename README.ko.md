# Agent Slity

[기본 README](README.md) · [English](README.en.md)

**작업에 꼭 필요한 팀을 구성하고 실행하세요.**

Agent Slity는 멀티에이전트 협업의 실제 효율을 측정하기 위한 오픈소스 개발자 도구를 개발하는 프로젝트입니다. 검증된 작업 품질을 유지하면서 중복 탐색, 불필요한 위임, 대기와 재시도를 줄이는 것이 목표입니다.

## 현재 상태

**0.4 개발 환경과 CI를 구축 중입니다.** 설치 가능한 앱, CLI, 수집기, 보고서 생성기와 데스크톱 UI는 아직 없습니다. 저장소 문서와 제외 규칙을 확인하는 기초 테스트를 제공합니다. 원격 CI의 실제 결과는 해당 PR에서 확인합니다. 기본 검증은 모델을 호출하지 않습니다.

초기 대상 환경은 Windows 11, WSL2 Ubuntu, Codex CLI입니다. 실제 지원 여부는 아직 검증하지 않았습니다. WSL 없는 Windows, Linux, macOS는 향후 대상입니다.

프로젝트 이름은 Agent Slity이며 저장소 이름은 `Agent-Slity`입니다. Google이나 OpenAI의 공식 제품이 아닌 독립 프로젝트입니다.

## 측정하려는 내용

- 여러 에이전트의 동일 파일·문서·명령 반복 탐색
- 작업 위임, 메시지 전달, 유휴 시간, 실패와 재시도
- 코드 변경에 대한 실제 검증 근거의 유무
- 요청한 모델 설정과 실행 중 관측한 증거의 차이
- 비교 가능한 팀 구성별 품질, 실행 시간, 관측된 사용량

모두 계획 중인 기능이며 구현이나 개선 효과를 입증한 상태가 아닙니다. 에이전트 수가 적다는 사실만으로 성공을 판단하지 않습니다. [0.2 선행 조사](docs/research/competitor-analysis.md)에서 주요 중복을 확인했으며, 차별화 가설과 성능 개선은 검증이 필요합니다.

## 데이터와 개인정보

첫 수집기는 모델 호출 없이 기존 로컬 Codex 실행 기록을 가져오는 방식으로 계획하고 있습니다. 출처와 불확실성을 보존하며, 사용량이 없으면 0이 아닌 `unknown`으로 남깁니다. 분석에서는 확인된 관측, 비효율 의심, 판단 정보 부족을 구분합니다.

현재는 로그를 수집하지 않습니다. 향후 공개 예제에는 합성 기록을 사용합니다. 인증 파일, 비밀 정보, 개인 대화와 원본 실행 로그를 Issue나 PR에 첨부하지 마세요. [보안 지침](SECURITY.md)을 확인하세요.

## 시작하기

현재 설치하거나 실행할 제품은 없습니다. 개발 도구를 사용하려면 Node.js 24와 Git을 설치한 뒤 저장소 루트에서 다음을 실행하세요.

```sh
npm ci
npm run check
```

`npm run check`는 타입 검사, 린트, 테스트와 빌드를 순서대로 실행합니다. Windows PowerShell에서는 `npm.cmd`를 사용할 수 있습니다. [기여 절차](CONTRIBUTING.md)와 [에이전트 작업 지침](AGENTS.md)도 확인하세요. 수집기와 보고서가 구현되면 모델 호출이 필요 없는 데모 명령을 안내합니다. 스크린샷은 실제 UI가 준비된 뒤 추가합니다.

## 로드맵

각 세부 단계는 별도의 명시적 요청으로 진행합니다. 한 단계의 완료는 다음 단계의 실행을 허용하지 않습니다.

| 단계 | 예정 산출물 |
| --- | --- |
| 0.1 | 완료: 공개 저장소와 최소 프로젝트 문서 |
| 0.2 | 완료: 독립적인 선행 조사와 차별화 가설 정리 |
| 0.3 | 완료: 코어/UI 분리와 증거 모델 설계 |
| 0.4 | 진행 중: 개발 도구, Issue/PR 템플릿과 CI |
| 1 | 모델 호출 없는 가져오기, 정규화, 스레드 연결과 JSON 내보내기 |
| 2 | 근거가 포함된 JSON·HTML 효율 보고서 |
| 3 | 명시적인 팀 선택과 이유를 설명하는 규칙 기반 추천 |
| 4 | 품질·시간·관측 사용량을 비교하는 재현 가능한 실험 |
| 5 | 검증된 코어를 사용하는 데스크톱 앱 |
| 6 | 선택적 Harness² 어댑터와 별도의 개선 실험 |
